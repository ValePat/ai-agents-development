# 🛡️ AI Agent Safety Guidelines

This document defines the mandatory safety and security procedures for interacting with AI agents and assistants (e.g., Gemini CLI, GitHub Copilot, Claude, ChatGPT, Cursor, etc.) within this project.

These guidelines apply to **all team members** and **any AI-powered tool** used in development.

---

## 1. Sensitive Data Protection

> **Never expose secrets, credentials, or personal data to any AI model.**

- **Environment Files**: Do not pipe or pass `.env` files directly to an AI assistant.
  - ❌ Avoid: `cat backend/.env | ai-tool "explain this"`
  - ✅ Best Practice: Manually describe the variable *name* without its value when asking for help.
- **API Keys & Credentials**: Ensure no keys (cloud providers, databases, third-party APIs) are present in your prompt context. Never expose API keys to the frontend or any UI layer.
- **Customer & User Data**: Before sharing error logs or database dumps with an AI tool, anonymize all names, email addresses, and IP addresses.

---

## 2. Context Management & Token Efficiency

> **Keep your prompts focused and context minimal to reduce cost and improve response quality.**

- **Model Selection** (when applicable):
  - Use lighter/faster models for quick questions, code explanations, or README generation.
  - Reserve larger/reasoning models for complex logic, architecture design, or debugging.
- **Reset Context Between Topics**: Clear chat history when switching to a different topic. Sending the full conversation history for every new question wastes tokens and increases noise.
- **Limit Output Length**: When your tool supports it, set a maximum token limit for responses (e.g., `--max-output-tokens 500` or equivalent).
- **Use Ignore Files**: Leverage tool-specific ignore files (e.g., `.geminiignore`, `.cursorignore`, `.copilotignore`) to prevent large or sensitive files from being automatically included in context.

---

## 3. Validation of AI-Generated Code

> **AI models can hallucinate — always review generated code before running it.**

- **No Blind Copy-Paste**: Never execute shell commands or scripts generated by an AI tool without first reviewing them manually.
- **Sanity Check**: Before running complex commands, test with `echo "command"` or run in a sandboxed environment (e.g., Docker container, local VM).
- **Dependency Audits**: If an AI suggests installing a new library, verify its popularity, maintenance status, and security record on [npm](https://www.npmjs.com/) or [PyPI](https://pypi.org/) before installing.
- **Prefer Sandboxed Tools**: When giving an AI agent access to your filesystem or shell, always use the sandboxed directory (`backend/sandbox/`) and never grant access to the project root.

---

## 4. Prompt Injection Awareness

> **Be cautious about content that the agent might read and interpret as instructions.**

- **Untrusted Input**: Do not feed user-submitted content directly into an agent's context without sanitization. A malicious user could craft input designed to override the agent's instructions.
- **File Content**: Be careful when asking an AI to "summarize" or "analyze" files that could contain adversarial instructions (e.g., `README.md` files from untrusted repositories).

---

## 5. Context Exclusion Files

The following file types must **never** be passed to an AI assistant (automatically or manually):

| Category         | Examples                                      |
|------------------|-----------------------------------------------|
| Secrets          | `.env`, `*.key`, `*.pem`, `credentials.json`  |
| Dependencies     | `node_modules/`, `venv/`, `__pycache__/`      |
| Build Artifacts  | `dist/`, `build/`, `.next/`                   |
| Lock Files       | `package-lock.json`, `poetry.lock`            |
| Logs & Databases | `*.log`, `*.sqlite`, `*.sql`                  |
| Binaries & Media | `*.exe`, `*.png`, `*.pdf`, `*.zip`            |

See [`.geminiignore`](../.geminiignore) for the active configuration used by Gemini CLI. Apply equivalent ignore rules for other tools.
