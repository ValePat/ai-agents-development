# Real-Time Show Orchestrator — Implementation Plan

## Summary

Build the "Conductor" system on top of the existing FastAPI/Next.js boilerplate. It adds a new `/orchestrator` FastAPI router to the existing backend, a Python interpolation engine that broadcasts OSC messages at 60 Hz, and a completely new Next.js director UI page (`/orchestrator`) alongside the existing chat page.

---

## Architecture Overview

```
Director's Browser (Next.js /orchestrator page)
        │  WebSocket (ws://localhost:8000/ws/orchestrator)
        ▼
FastAPI backend/main.py  ──► /orchestrator/* router
        │
        ├─► LLM Agent (Gemini Flash via OpenRouter + LiteLLM)
        │       └─► structured JSON: { energy, tension, rhythm_density, atmosphere, duration }
        │
        ├─► InterpolationEngine (asyncio task, 60 Hz loop)
        │       └─► smooth current_values → target_values over `duration` seconds
        │               with optional ease-in-out curve
        │
        └─► OSC Dispatcher (python-osc, UDP broadcast)
                ├─► Ableton Live / Max for Live  (port 9000)
                └─► TouchDesigner OSC In CHOP    (port 9001)
```

---

## User Decisions

| Decision | Choice |
|---|---|
| LLM for macro translation | Gemini Flash via OpenRouter |
| Integration style | New FastAPI router in same `backend/main.py` |
| WebSocket transport | Native FastAPI WebSockets |

## Backend Changes

### 1. New Python modules under `backend/orchestrator/`

#### `backend/orchestrator/__init__.py`
Empty init to make it a package.

#### `backend/orchestrator/models.py`
Pydantic schemas shared across the orchestrator:
```python
class MacroState(BaseModel):
    energy: float = 0.5           # 0.0–1.0
    tension: float = 0.5
    rhythm_density: float = 0.5
    atmosphere: float = 0.5

class MacroTarget(MacroState):
    duration: float = 4.0         # seconds for the transition

class PromptRequest(BaseModel):
    prompt: str
    override: Optional[MacroState] = None   # hard-override from UI sliders

class OrchestratorStatus(BaseModel):
    current: MacroState
    target: MacroTarget
    is_interpolating: bool
    elapsed_seconds: float
```

#### `backend/orchestrator/llm_agent.py`
Calls Gemini Flash via LiteLLM with a strict `response_format={"type": "json_object"}` instruction. Returns a validated `MacroTarget`.

- Prompt template embeds the 4 macro descriptions and the user's semantic input.
- Model: `"openrouter/google/gemini-3.1-flash-lite"` (configurable via `ORCHESTRATOR_MODEL_ID` env var with this default).
- Uses the existing `LiteLLMModel` pattern from `main.py`.
- Raises a typed `LLMTranslationError` on parse failure so the endpoint can return a clean 422.

#### `backend/orchestrator/interpolation_engine.py`
Core async engine:

```python
class InterpolationEngine:
    current: MacroState          # live values sent to OSC
    target: MacroTarget          # destination
    _task: asyncio.Task          # 60 Hz loop
    _override: set[str]          # variables pinned by manual sliders

    async def set_target(self, target: MacroTarget): ...
    def hard_override(self, field: str, value: float): ...
    def release_override(self, field: str): ...
    async def _loop(self): ...   # 60 Hz, easing curves, OSC dispatch
```

Easing: `ease_in_out(t) = t*t*(3 - 2*t)` (smoothstep). Linear mode also supported for "snap" transitions when `duration < 0.5s`.

Progress is tracked with `elapsed / (duration * 60)`. When progress reaches 1.0, the loop parks at target values and becomes idle (no CPU waste).

#### `backend/orchestrator/osc_dispatcher.py`
Wraps `python-osc`'s `SimpleUDPClient`. Two clients: one for Ableton (`ABLETON_OSC_HOST/PORT`), one for TouchDesigner (`TD_OSC_HOST/PORT`). Configurable via env vars with sensible defaults:

```
ABLETON_OSC_HOST=127.0.0.1   ABLETON_OSC_PORT=9000
TD_OSC_HOST=127.0.0.1        TD_OSC_PORT=9001
```

Sends 4 messages per tick:
```
/orchestrator/energy          <float>
/orchestrator/tension         <float>
/orchestrator/rhythm_density  <float>
/orchestrator/atmosphere      <float>
```

#### `backend/orchestrator/router.py`
FastAPI `APIRouter` with prefix `/orchestrator`:

| Method | Path | Description |
|--------|------|-------------|
| `GET`  | `/status` | Returns current `OrchestratorStatus` |
| `POST` | `/prompt` | Accepts `PromptRequest`, runs LLM, sets target |
| `POST` | `/override` | Accepts `MacroState` + field name, pins a slider value |
| `DELETE` | `/override/{field}` | Releases a pinned field back to interpolation |
| `WebSocket` | `/ws` | Streams `OrchestratorStatus` JSON at ~10 Hz to frontend |

### 2. Changes to `backend/main.py`

- Import and `app.include_router(orchestrator_router, prefix="/orchestrator")`.
- Instantiate `InterpolationEngine` as a singleton inside the existing `lifespan` context manager (started and cleaned up alongside MCP servers).
- Add `ORCHESTRATOR_MODEL_ID` and OSC env vars to `.env` documentation (not hard-coded secrets).
- Expand CORS `allow_origins` to keep `localhost:3000`.

### 3. `backend/requirements.txt` additions

```
python-osc
```

(LiteLLM is already present; no other new deps needed for the backend.)

## Frontend Changes

### New page: `frontend/app/orchestrator/page.tsx`

Full-screen dark "director's console" aesthetic matching the existing dark/purple theme.

#### Layout (3 zones):

**Zone A — Prompt Input (top)**
- Large `<textarea>` for multi-word semantic prompts.
- "Transition Duration" number input (seconds, defaults to 4).
- "Send to Orchestrator" button → `POST /orchestrator/prompt`.
- Shows the LLM's returned macro targets as a preview toast before they apply.

**Zone B — Live Macro Visualizer (center)**
- 4 animated bar/gauge widgets (one per macro: Energy, Tension, Rhythm Density, Atmosphere).
- Values driven by the WebSocket stream (`ws://localhost:8000/orchestrator/ws`).
- Interpolation progress shown as a subtle progress arc.
- Each bar subtly glows when that variable is being actively overridden.

**Zone C — Emergency Override Panel (bottom)**
- 4 range sliders (0–100, displayed as 0.0–1.0).
- Moving a slider immediately calls `POST /orchestrator/override` with `{ field, value }`.
- Releasing the slider (on `pointerup`) with a "Release" toggle button calls `DELETE /orchestrator/override/{field}`.
- Clear visual state: pinned = amber border; interpolating = green pulse.

#### Phase 4 — Rehearsal / Tuning Mode

A collapsible "Rehearsal Panel" accessible via a toggle button:
- **Preset bank**: save/load named macro snapshots (e.g., "Build", "Peak", "Breakdown") stored in `localStorage`.
- **Macro tuning sliders**: permanently adjust min/max clamping ranges per macro (stored in `localStorage`, sent as a calibration call to `/orchestrator/calibrate`).
- **Transition preview**: sends a target without committing, shows a time-lapse preview of the transition curve.
- **OSC monitor**: displays last-sent OSC values in a small log for the programmer to verify signal flow.

### New component: `frontend/components/orchestrator/MacroGauge.tsx`

Animated gauge using CSS transitions on a `<div>` width. Props: `{ name, value, isOverridden, isInterpolating }`. Keeps components small and reusable as per `AGENTS.md` conventions.

### New component: `frontend/components/orchestrator/OverrideSlider.tsx`

Range slider with `onPointerMove` (debounced ~50ms) for live override and release toggle button.

### New component: `frontend/components/orchestrator/PresetBank.tsx` (Phase 4)

Preset save/load UI backed by `localStorage`.

### Navigation

Add a subtle nav link in `frontend/app/layout.tsx` so users can switch between the existing Chat page and the new Orchestrator page.

## Implementation Phases

### Phase 1 — OSC Pipeline Proof of Concept
1. Create `backend/orchestrator/` package with `models.py`, `osc_dispatcher.py`, and a minimal `interpolation_engine.py`.
2. Add `python-osc` to `requirements.txt`.
3. Wire engine startup in `main.py` lifespan.
4. Add `GET /orchestrator/status` and a simple `POST /orchestrator/prompt` stub (echoes a hardcoded `MacroTarget` without LLM).
5. Verify OSC messages arrive in TouchDesigner/Ableton (or `oscdump` for testing).

### Phase 2 — LLM Integration + Interpolation Logic
6. Implement `llm_agent.py` with Gemini Flash structured output.
7. Implement full `interpolation_engine.py` with ease-in-out, 60 Hz loop, and override pin/release logic.
8. Wire LLM agent into `POST /orchestrator/prompt`.
9. Implement WebSocket endpoint `/orchestrator/ws` streaming status at 10 Hz.

### Phase 3 — Director's UI
10. Create `MacroGauge.tsx` and `OverrideSlider.tsx` components.
11. Build `frontend/app/orchestrator/page.tsx` with all 3 zones.
12. Connect WebSocket for live macro display.
13. Wire prompt form to `POST /orchestrator/prompt`.
14. Wire override sliders to `POST/DELETE /orchestrator/override/{field}`.
15. Add nav link in `layout.tsx`.

### Phase 4 — Rehearsal Tooling
16. Create `PresetBank.tsx` and integrate into the page.
17. Add `POST /orchestrator/calibrate` endpoint for min/max clamping.
18. Build collapsible Rehearsal Panel with preset bank, calibration sliders, transition preview, and OSC monitor.
19. Document the full orchestrator architecture in `docs/ORCHESTRATOR.md`.

## Key Design Decisions & Rationale

| Decision | Rationale |
|---|---|
| Single backend (`main.py` + router) | Avoids new Docker service, reuses existing LiteLLM/CORS setup. |
| Gemini Flash | Low latency (~0.5–1s) is critical; the 2s budget allows one LLM call + engine handoff. |
| `asyncio` 60 Hz loop, not a thread | Already async FastAPI; avoids GIL contention on the hot dispatch path. |
| WebSocket at 10 Hz (not 60 Hz) | Browser does not need 60 Hz visual updates; saves bandwidth. OSC dispatch stays at 60 Hz. |
| `localStorage` for presets | No backend state needed; keeps the system stateless between sessions. |
| Separate OSC ports for Ableton / TD | Allows independent routing; Ableton and TD can run on different machines on the LAN. |
| Smoothstep easing | Simple to implement (`3t² - 2t³`), visually pleasing, no external math deps. |

## Testing Strategy

- **Unit**: `pytest` tests for `InterpolationEngine` step math and easing curve correctness.
- **Integration**: `/orchestrator/prompt` with a mocked LLM returning a known `MacroTarget`; assert OSC packet content via a UDP listener.
- **Frontend**: Manual rehearsal-mode test with `oscdump` to verify 60 Hz OSC output and UI slider override behavior.
